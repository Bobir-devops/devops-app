Linux — shahar
DevOps Learning · 1/6
Process — kim ishlayapti
ps aux — butun fotosurat
ps aux --sort=-%cpu | head — ochko'zlar
ps aux --sort=-%mem | head — xotira
pgrep -a nginx — ism bilan topish
top / htop — jonli monitor
docker top / kubectl top — quti ichida
Signal — to'xtatish
kill PID — SIGTERM: "yig'ishtir va chiq"
kill -9 PID — SIGKILL: rubilnik
exit 143 = SIGTERM · 137 = SIGKILL/OOM
zombie = ota imzolamagan · orphan → PID 1
systemd — dispetcher
systemctl status X — chiroq qaysi rang
start / stop — hozir yoq / o'chir
restart — buzib qayta (downtime)
reload — yangi yo'riqnoma (downtimesiz)
enable --now — boot ro'yxati + hozir
journalctl -u X -n 50 — qora kitob
journalctl -f jonli · -b bootdan · -k kernel
Disk va fayl
df -h — joy · df -i — inode (boshqa narsa!)
du -sh /var/* — kim yeyapti
lsof +L1 — o'chirilgan, lekin ochiq fayl
ls -li — inode raqami (hard link tekshiruvi)
ln a b hard · ln -s a b symlink
ulimit -n · lsof -p PID — FD chiptalari
Ruxsat — 4·2·1
r=4 w=2 x=1 · owner group other
755 skript/papka · 644 oddiy fayl · 600 kalit
papkada x = "ichkariga kirish", ishga tushirish emas
Xotira
free -h → ps --sort=-%mem → journalctl -k
load average = navbat / kassa (yadro) soni
1 > 15 — o'syapti · swap ko'p → thrashing
Tekshiruv zanjiri
1. process tirikmi — pgrep -a
2. eshik ochiqmi — ss -lntup
3. xizmat holati — systemctl status
4. resurs — free -h, df -h
5. log — journalctl -n 50
Networking — pochta
DevOps Learning · 2/6
Manzil va yo'l
ip addr — manzilim bormi?
ip route — tashqariga yo'lim bormi?
ip route get 8.8.8.8 — qaysi yo'ldan
ip neigh — ARP: bu IP kimda?
/24 = 256 manzil · birinchi = network
oxirgi = broadcast · default gw = 0.0.0.0/0
Eshik va nom
ss -lntup — kim qaysi portda eshityapti
nc -vz host port — TCP ulanadimi
getent hosts X — tizim qanday ko'radi
dig X / dig @8.8.8.8 X +short — DNS to'g'ridan
curl -I https://X — HTTPS javobi
dig ishlab getent ishlamasa → resolv.conf
Timeout va refused
timeout = sukunat — javob kelmadi: DNS, route, firewall DROP, tarmoq, server o'lik. Butun zanjir tekshiriladi.
refused = rad javobi — paket yetib bordi, o'sha portda listener yo'q. Bitta joy: ss -lntup.
Qavatlar
L2 MAC · L3 IP · L4 TCP/UDP · L7 HTTP/DNS/SSH
TCP: SYN → SYN-ACK → ACK
ishonchlilik: seq + ACK + retransmit + window
UDP: handshake yo'q, kafolat yo'q, tez
DNS recordlar
A IPv4 · AAAA IPv6 · CNAME alias
MX pochta · TXT metadata · NS authoritative
PTR teskari · TTL — cache umri
propagation = TTL tugashini kutish
NAT va HTTP
SNAT = chiqish · DNAT = kirish (port forward)
4xx clientda · 5xx serverda
502 yaroqsiz javob · 504 javob kechikdi
401 autentifikatsiya · 403 ruxsat · 429 ko'p so'rov
Narvon — pastdan yuqoriga
Name → IP → Route → TCP port → TLS/HTTP → Application. Har pog'onada bitta savol, bitta buyruq.
Docker — qutixona
DevOps Learning · 3/6
Yo'nalish
Dockerfile → build → Image → run → Container → Application. Container to'rt o'lchamda: process, network, filesystem, resources.
Dockerfile
FROM asos · WORKDIR katalog · COPY fayl
RUN build vaqtida · CMD run vaqtida
ENTRYPOINT ijrochi + CMD argument
EXPOSE faqat hujjat — port ochmaydi
USER root'dan chiqish · ENV sozlama
cache: dependency yuqorida, COPY . . pastda
Kundalik buyruqlar
docker ps -a — exit code bilan
docker logs -f --tail 50 X
docker inspect X — OOMKilled, CMD, mount
docker exec -it X sh — ichkariga kirish
docker top X — PID 1 kim?
docker stats — CPU, xotira, I/O
docker system df / prune — disk
Eng ko'p uchraydigan xato
Dastur 127.0.0.1ga bind qilingan → hostdan yetib borilmaydi. 0.0.0.0ga bind qilinishi kerak. Tekshirish: docker exec -it X ss -lntup.
Tarmoq va volume
-p 8000:8000 — DNAT (haqiqiy ochish)
container localhost = o'zi, host emas
nom orqali topish → o'z tarmog'ida (bridge emas)
docker network create app-net + connect
-v vol:/path volume · -v /host:/path bind
holat container ichida turmaydi
Resurs va signal
-m 512m — oshsa OOMKilled (137)
--cpus=1.5 — oshsa throttling (sekinlashadi)
xotira o'ldiradi, CPU sekinlashtiradi
exec form CMD → PID 1 dastur → SIGTERM yetadi
Zanjir
darhol chiqdi → ps -a, logs, inspect
ishlayapti-yu javob yo'q → log → process → port → bind → tarmoq → config → dependency
Kubernetes — zavod
DevOps Learning · 4/6
So'rovning yo'li
kubectl → API server (auth → admission → etcd) → scheduler → kubelet → runtime → Pod.
Trafik: DNS → LB → Ingress → Service → Pod.
Kundalik buyruqlar
kubectl get pods -o wide
kubectl describe pod X — events, exit code
kubectl logs X --previous — o'lgan konteyner
kubectl get endpoints X — bo'shmi?
kubectl exec -it X -- sh
kubectl rollout status|undo deploy/X
kubectl top pods · get events --sort-by=...
Xato lug'ati
Pending — joy yo'q / taint / PVC kutyapti
ImagePullBackOff — teg, repo yoki secret
CrashLoopBackOff — dastur yiqilyapti → logs
OOMKilled (137) — limitga urildi
Terminating qotdi — finalizer / grace
NotReady node — kubelet, pressure, CNI
Probe
readiness — trafik bermi? (endpointdan chiqaradi)
liveness — tirikmi? (qayta ishga tushiradi)
startup — sekin startga vaqt beradi
liveness juda qattiq → cheksiz restart
Obyektlar
Deployment → ReplicaSet → Pod (stateless)
StatefulSet — barqaror nom va disk
DaemonSet — har node'da bitta
Job / CronJob — bir martalik / jadvalli
Service ClusterIP/NodePort/LoadBalancer
ConfigMap ochiq · Secret maxfiy · PVC disk
Resurs va availability
requests — rejalashtirish uchun kafolat
limits — yuqori chegara (xotira o'ldiradi)
anti-affinity — bir node'ga to'planmaslik
topologySpreadConstraints — zonalarga yoyish
PDB — drain paytida minimal nusxa
cordon → drain → yangilash → uncordon
Service ishlamasa
1. Service nomi (DNS) → 2. selector labelga mos → 3. endpoints bo'shmi → 4. readiness → 5. port/targetPort → 6. dastur 0.0.0.0 da → 7. NetworkPolicy
